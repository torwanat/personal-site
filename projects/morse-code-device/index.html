Morse Code Device - an embedded Morse-code input, playback and translation device.

Built on a Raspberry Pi Pico with FreeRTOS, the device lets users enter Morse code with buttons, detects orientation with an IMU, and plays or translates messages through a buzzer, display, and USB serial connection.

Back to projects overview

Overview

Morse Code Device is a group coursework project built around a Raspberry Pi Pico and FreeRTOS. The user enters dots and dashes with two physical buttons: the device determines whether a press should register as a dot or a dash based on its orientation, measured by an ICM-42670 IMU. Messages can be played through the buzzer, translated from Morse code to text, shown on the display, and sent over USB serial.


  • Areas: Embedded systems, RTOS programming, C, Human-device interaction
  • Tech: Raspberry Pi Pico, FreeRTOS, C, ICM-42670 IMU, buzzer, display

Tech stack and architecture

The firmware is written in C and uses FreeRTOS to separate concerns into concurrent tasks: IMU reading, button handling, USB transmission, USB command reception, and menu display. GPIO interrupts capture button presses, while shared state variables and message buffers coordinate communication between tasks. The Pico SDK provides access to the TKJHAT peripherals, including the display, buzzer, LED, buttons, and IMU.

Morse input

  • Button 1 adds a dot or dash
  • IMU orientation selects dot versus dash
  • Button 2 inserts a space
  • Three spaces mark the end of a message
  • Buzzer gives audible feedback for each input

Translation and output

Morse sequences are decoded using a binary-tree-style lookup table. Completed messages can be printed as Morse code and translated text over USB serial, displayed as text on the LCD, and replayed through the buzzer with distinct tones and timing for dots, dashes, and spaces.

Extras

  • USB commands: /led, /buzzer, /clear, and /play
  • Menu for selecting one of three buzzer songs
  • LED blink confirmation when a message is sent
  • FreeRTOS tasks with scheduled delays and interrupt-driven buttons

Implementation details

The application uses a small state machine with states for reading input, preparing and sending messages, processing USB commands, navigating the menu, and playing songs. This makes it clear which task should act at any given time and prevents button or serial input from interfering with ongoing playback.


Concurrency

Five FreeRTOS tasks run concurrently: one reads IMU data and updates orientation, one handles button presses and Morse entry, one sends completed messages over USB, one receives and processes serial commands, and one updates the menu display. Button events are captured through GPIO edge interrupts and consumed by the button task.


Morse decoding

Dots and dashes are stored in a message buffer. At translation time, the decoder traverses a compact lookup structure: a dot moves to the left branch and a dash to the right branch, while a space emits the current character and resets traversal. This avoids storing a large dictionary of individual Morse codes.


Build environment

The project is built with CMake, the Raspberry Pi Pico SDK, and FreeRTOS Kernel 11.2.0. The repository also documents a complete Linux and VS Code development setup, including toolchain installation, USB device permissions, OpenOCD debugging support, and Pico extension configuration.

What I learned

This project gave hands-on experience with embedded C development on the Raspberry Pi Pico, FreeRTOS task creation and scheduling, interrupt-driven input, and coordinating shared state between concurrent tasks. It also involved integrating several hardware peripherals—I2C display, IMU, buzzer, LED, and buttons—into one responsive device, as well as collaborating on a shared codebase as part of coursework.
